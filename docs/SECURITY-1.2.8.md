# 1.2.8 敏感操作验证修复

本版修复已登录管理员会话绕过现有 2FA 的两条路径；服务端必须搭配本版前端，升级后刷新已打开的管理页面。无需数据库结构迁移，已绑定验证器、节点、GitHub 登录、延迟任务和 DDNS 配置继续保留。

- **首次启用与更换验证器分开处理。** 新密钥仅由服务端生成。更换前必须验证当前验证器；通过后领取与用户及当前登录会话绑定、有效期 5 分钟的临时配置凭据。浏览器 Cookie 只保存随机 ID，服务端不再接受旧 `2fa_secret` Cookie 提供的密钥。
- **确认新验证器才切换。** 新验证码错误最多重试 5 次；配置凭据只能成功消费一次。原因素发生变化时，数据库条件更新拒绝覆盖；成功启用、更换或停用后，清除该用户所有待完成配置。个人 2FA 操作必须使用登录会话，不能使用全局 API Key。
- **API Key 按敏感凭据处理。** 普通设置响应不再返回完整 Key，仅返回 `api_key_configured`。已启用 2FA 的账号创建、更换、清空及单独查看 Key 均需当前验证码；验证失败时整个设置请求不写入。前端使用密码输入框和安全随机数，已保存 Key 只按需临时显示，60 秒后自动隐藏。
- **导出及恢复完整备份要求二次验证。** 备份包含账号因素及凭据；导出受保护，恢复也受保护以避免通过替换数据库绕过验证。未验证上传不会为查找验证码而读取整个 multipart 文件。原有备份恢复内容校验与事务性不在本补丁范围内。
- **验证输入及频率。** 前端不将验证码写入 URL，而使用请求头或 JSON 请求体。已有因素验证按账号限制为每分钟最多 10 次；缺少验证码直接拒绝。敏感响应不缓存，验证码及配置状态元数据不写入设置表。

已持有有效 API Key 的自动化继续拥有原有管理员权限；本版阻止只有普通会话的调用者无验证码取得或创建这个凭据。没有启用 2FA 的账号保留原有访问行为。API Key 是高权限凭据，不是一个额外的低权限登录方式。

## 验证

- 实际身份中间件及完整路由回归：无登录/仅会话请求被拒绝；Key 创建、轮换、删除、查看、备份导出及恢复入口均受保护，普通设置正常保存。
- 2FA 生命周期回归：伪造旧 Cookie、跨会话、跨用户、过期、错误次数、旧因素变化、停用后的凭据以及并发重放；正确首次绑定、更换及停用仍可完成。
- 备份正向回归：提供正确验证码后可下载有效 SQLite ZIP，账号因素按备份语义保留。
- 前端回归：验证码仅进入请求头、失败导出不会下载、API Key 使用浏览器密码学随机数；TypeScript 和生产构建。

Agent 没有新增协议或功能变更，使用原有代码按 1.2.8 标签重新构建，以统一发布和节点版本。
